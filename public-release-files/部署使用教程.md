> **更新日期**：2026-06-11
> **架构模式**：宝塔Nginx（SSL终止）→ Caddy（HTTP内部反代）→ Docker容器

## 三、域名准备

需要准备**3个子域名**，全部解析到服务器IP：

| 域名 | 用途 | 示例 |
|------|------|------|
| 管理后台 | 商户登录管理商城 | `admin.yourdomain.com` |
| H5商城 | 顾客手机访问的商城 | `h5.yourdomain.com` |
| API接口 | 后端API服务 | `api.yourdomain.com` |

**DNS设置**：在域名管理后台，为3个子域名各添加一条A记录，指向服务器公网IP。

### SSL证书说明

本系统采用**宝塔+Caddy共存架构**：SSL证书由宝塔面板自动申请和管理，Caddy仅在内部网络以HTTP模式运行。

**无需手动配置SSL证书**，只需在宝塔面板中为每个站点申请Let's Encrypt免费证书即可（详见第五节）。

## 四、部署步骤

### 第1步：进入部署目录

推荐将系统部署到 `/opt` 目录下：

```bash
cd /opt
```

### 第2步：克隆仓库

```bash
git clone https://github.com/renjie2026/fenglianshop-open.git
cd fenglianshop-open
```

> 如果克隆时遇到 `HTTP2 framing layer` 错误，请使用 HTTP/1.1 协议重试：
> ```bash
> git -c http.version=HTTP/1.1 clone https://github.com/renjie2026/fenglianshop-open.git
> cd fenglianshop-open
> ```

### 第3步：配置环境变量

```bash
cp .env.example .env
```

**必须修改的三项域名配置**（把 `yourdomain.com` 换成你的真实域名）：

```bash
sed -i 's|https://admin.yourdomain.com|https://admin.你的域名.com|g' .env
sed -i 's|https://h5.yourdomain.com|https://h5.你的域名.com|g' .env
sed -i 's|https://api.yourdomain.com|https://api.你的域名.com|g' .env
```

**验证修改结果：**

```bash
head -5 .env
```

输出应显示三个域名已替换为你的真实域名。

### 第4步：一键启动

```bash
bash start.sh
```

脚本会自动完成以下操作：
1. 检查Docker和Docker Compose是否安装
2. 校验域名格式和DNS解析
3. 首次运行自动生成MySQL数据库强密码（`DB_PASSWORD` 和 `MYSQL_ROOT_PASSWORD`），自动生成后写入 `.env` 文件并显示一次，请务必记录。**注意：这不是管理后台登录密码，管理后台默认账号admin，密码123123**
4. **检测到国内网络后自动配置 Docker 镜像加速器**（`docker.1panel.live`）并重启 Docker
5. 生成Caddy反向代理配置（HTTP-only内部路由）
6. 拉取Docker镜像
7. 启动全部容器
8. 等待MySQL和Redis健康检查通过
9. 安装每日凌晨3点自动备份任务
10. 输出访问地址和默认账号密码

> **备用镜像源**：如果 `docker.1panel.live` 拉取失败，可手动切换其他镜像源：
>
> ```bash
> # 切换为 mirror.baijiayun.com（北京云）
> echo '{"registry-mirrors":["https://mirror.baijiayun.com"]}' > /etc/docker/daemon.json
> systemctl daemon-reload && systemctl restart docker
> bash start.sh
> ```
>
> **恢复直连 Docker Hub**（无镜像加速）：
> ```bash
> echo '{}' > /etc/docker/daemon.json
> systemctl daemon-reload && systemctl restart docker
> bash start.sh
> ```

### 第4.5步：安装公开版自动更新守护进程

首次部署成功后，继续在宿主机执行：

```bash
sudo bash ./update-toolkit/install-public-update-daemon.sh
```

作用说明：

1. 创建 `update-toolkit/.queue` 与 `logs` 目录。
2. 安装 `fenglianshop-public-update-daemon` systemd 服务。
3. 让管理后台”系统升级 -> 立即更新”可以把任务写入队列并由宿主机执行 `docker compose pull/up -d`。

安装完成后检查：

```bash
systemctl status fenglianshop-public-update-daemon --no-pager
journalctl -u fenglianshop-public-update-daemon -f
```

### 第5步：配置宝塔反向代理

Docker容器启动后，需要在宝塔面板配置反向代理，让域名通过HTTPS访问系统。

#### 5.1 创建站点

在宝塔面板 → 网站 → 添加站点，分别创建3个站点：

| 站点 | 域名 | PHP版本 |
|------|------|---------|
| 管理后台 | 你的admin域名 | 纯静态 |
| H5会员端 | 你的h5域名 | 纯静态 |
| API接口 | 你的api域名 | 纯静态 |

#### 5.2 申请SSL证书

每个站点 → SSL → Let's Encrypt → 申请免费证书，开启强制HTTPS。

#### 5.3 配置反向代理

**每个站点**添加反向代理，配置完全相同：

- 代理名称：`fenglianshop`
- 目标URL：`http://127.0.0.1:8880`
- 发送域名：保持默认 `$host`

> **重要**：发送域名必须保持 `$host`，不能改成IP。Caddy根据Host头分派域名路由。

#### 5.4 （可选）手动编辑Nginx配置

如果宝塔的反代配置不完善，可以手动编辑Nginx配置，确保包含以下关键头部：

```nginx
location / {
    proxy_pass http://127.0.0.1:8880;

    # 关键头部
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # WebSocket支持
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";

    # 超时设置
    proxy_connect_timeout 60s;
    proxy_read_timeout 300s;

    # 修复重定向
    proxy_redirect http:// https://;
}
```

> **注意**：`proxy_pass` 末尾**不能有斜杠** `/`，否则会导致URL被截断。

#### 5.5 防火墙屏蔽8880端口

为防止用户绕过SSL直接通过 `http://域名:8880` 访问，建议屏蔽8880端口的外部访问：

```bash
# 方法1：宝塔面板 → 安全 → 防火墙 → 不放行8880端口
# 方法2：命令行
iptables -A INPUT -p tcp --dport 8880 -s 127.0.0.1 -j ACCEPT
iptables -A INPUT -p tcp --dport 8880 -j DROP
```

### 第6步：访问系统

### 第7步：后台授权激活

登录管理后台后，进入`升级与授权 -> 系统升级`：

1. 先点击“免费获取授权码”或从更新平台获取授权码。

## 五、端口与域名说明

### 架构说明

本系统采用**宝塔+Caddy共存架构**：

```
用户浏览器 → 宝塔Nginx(:443, SSL终止) → Caddy(:8880, HTTP内部) → Docker容器
```

- **宝塔Nginx**：监听80/443端口，处理SSL证书、强制HTTPS跳转
- **Caddy**：监听8880端口（仅内部），根据Host头将请求分派到不同容器
- **Docker容器**：admin/h5/nginx-api 各自运行在内部80/9000端口

3个域名（admin/h5/api）全部通过Caddy的**同一个8880端口**内部路由，宝塔根据域名配置各自的反向代理。

### MySQL和Redis端口

MySQL(3306)和Redis(6379)只在Docker内部网络通信，**不对外暴露**。

这意味着：如果同一台服务器上部署了多套本系统（例如用不同目录），每套的MySQL都用3306端口，**互不冲突**——因为它们在各自独立的Docker网络中，就像每套房子里都有一个"1号房间"，但房子是隔开的。

| 端口 | 对外暴露？ | 说明 |
|------|-----------|------|
| 80 | ✅ 是 | 宝塔Nginx HTTP（自动跳转HTTPS） |
| 443 | ✅ 是 | 宝塔Nginx HTTPS（用户实际访问） |
| 8880 | ❌ 否（建议屏蔽） | Caddy内部HTTP（宝塔反代目标） |
| MySQL 3306 | ❌ 否 | Docker内部通信，多套部署不冲突 |
| Redis 6379 | ❌ 否 | Docker内部通信，多套部署不冲突 |

## 六、修改内部端口

默认内部端口为 `8880`（Caddy HTTP）。如果8880端口被占用，可在 `.env` 中修改：

```env
HTTP_PORT=9080
```

修改后重新运行 `bash start.sh` 生效。同时需要更新宝塔反向代理的目标URL为新端口。

**注意**：80和443端口由宝塔Nginx使用，Caddy仅使用内部端口（默认8880）。

## 七、密码持久化与更新说明

### 部署文件夹结构

部署后，所有文件都在同一个文件夹中：

```
fenglianshop-open/          ← git clone 创建的文件夹
├── docker-compose.yml      ← 容器编排配置
├── .env                    ← 环境变量（含数据库密码，自动生成）
├── Caddyfile               ← Caddy反代配置（start.sh自动生成）
├── start.sh                ← 一键部署脚本
├── backup.sh               ← 备份脚本
├── restore.sh              ← 恢复脚本
├── backups/                ← 备份文件目录（自动创建）
└── ...
```

### 密码如何持久化？

首次运行 `start.sh` 自动生成的MySQL密码会**写入 `.env` 文件**。以后每次运行 `start.sh` 或 `docker compose up -d`，Docker都会从 `.env` 读取密码，**不会重新生成**。

### 如何更新到新版本？

```bash
# 1. 拉取最新代码（.env不会被覆盖，因为.gitignore已排除）
git pull

# 2. 修改 .env 中的 VERSION 为新版本号
# 例如：VERSION=v6.20260610.001

# 3. 重新拉取镜像并启动（密码从.env读取，无需重新输入）
bash start.sh
```

**关键**：`.env` 文件被 `.gitignore` 排除，所以 `git pull` 不会覆盖你已有的密码配置。

## 十、宝塔SSL证书说明

SSL证书由**宝塔面板**自动管理，Caddy不处理任何SSL。

- **申请方式**：宝塔面板 → 网站 → 对应站点 → SSL → Let's Encrypt → 申请
- **续期周期**：宝塔自动续期，无需手动操作
- **强制HTTPS**：建议在每个站点的SSL设置中开启"强制HTTPS"

如果证书申请失败，检查：

1. **域名解析**：确认域名A记录已指向服务器IP
2. **端口开放**：确认80和443端口未被防火墙拦截
3. **宝塔日志**：宝塔面板 → 网站 → 对应站点 → 日志

## 十一、常见问题

### Q1: 端口被占用怎么办？

```bash
# 检查8880端口占用
ss -tlnp | grep 8880

# 如果被占用，修改.env中的端口号
HTTP_PORT=9080

# 重新启动（同时更新宝塔反代目标端口）
bash start.sh
```

### Q2: 国内服务器拉取镜像很慢？

脚本会自动检测国内网络并尝试镜像加速。如果出现 `pull access denied for registry.cn-hangzhou.aliyuncs.com/library/caddy` 错误，是因为阿里云镜像仓库没有 Caddy 镜像，执行以下命令切换到官方源：

```bash
sed -i '/CADDY_IMAGE/d' .env
echo 'CADDY_IMAGE=caddy:2-alpine' >> .env
bash start.sh
```

### Q3: 如何更新到新版本？

```bash
# 1. 确认守护进程在线
systemctl status fenglianshop-public-update-daemon --no-pager

# 2. 登录后台 → 升级与授权 → 系统升级
# 3. 激活授权后执行“检查更新 / 立即更新”
```

### Q4: 忘记数据库密码？

```bash
# 密码保存在 .env 文件中
grep "DB_PASSWORD" .env
```

### Q5: 如何完全卸载？

```bash
# 先停止服务
docker compose stop

# 如需再执行容器清理，请先确认已完成数据库备份
docker compose down
```

> 严禁直接执行 `docker compose down -v`，这会删除数据库卷和 Redis 数据，属于不可逆操作。

## 十二、容器架构

```
用户浏览器
    ↓ HTTPS
宝塔Nginx (:443, SSL终止)
    ↓ proxy_pass http://127.0.0.1:8880
Caddy (:8880, HTTP-only内部反代)
    ├── admin.yourdomain.com → admin容器:80
    ├── h5.yourdomain.com    → h5容器:80
    └── api.yourdomain.com   → nginx-api容器:80
                                    ↓
                              api容器:9000 (PHP-FPM)
                                    ↓
                            ┌───────┴───────┐
                        MySQL:3306      Redis:6379
```

共7个容器：MySQL + Redis + API + nginx-api + Admin + H5 + Caddy

- **宝塔Nginx**：宿主机运行，处理SSL和反向代理
- **Caddy**：Docker容器，仅内部HTTP路由，根据Host头分派请求
- **nginx-api**：API容器的Web前端，转发PHP请求给api:9000

公开版升级链路补充：

- API 容器只写入 `update-toolkit/.queue/commands.json` 和 `.trigger`。
- 宿主机 `fenglianshop-public-update-daemon` 服务串行处理升级命令。
- 公开版只支持 Docker Hub 公开仓库，不需要 `docker login`。
- 不需要把 `/var/run/docker.sock` 挂载进 API 容器。
