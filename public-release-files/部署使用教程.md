## 一、文件说明

本文件夹（`public-release-files/`）是公开仓库（fenglianshop-open）的部署工具包，包含一键部署所需的所有文件。

**推荐安装方式**：使用 `install.sh` 一键下载，自动创建 `/opt/fenglianshop` 目录并放入部署文件。

| 文件 | 用途 |
|------|------|
| `install.sh` | 一键下载部署工具包脚本（推荐使用） |
| `docker-compose.yml` | Docker容器编排配置（8个服务） |
| `.env.example` | 环境变量模板（域名、端口、数据库） |
| `start.sh` | 一键部署脚本（检查环境→生成配置→启动容器→交互安装） |
| `update-toolkit/` | 公开版宿主机更新守护进程与队列执行脚本 |
| `fix-bt-proxy-pass.sh` | 宝塔反代优化修复脚本 |
| `backup.sh` | 数据库备份脚本 |
| `restore.sh` | 数据库恢复脚本 |
| `部署使用教程.md` | 完整详细教程 |
| `.dockerignore` | Docker构建排除规则 |

## 三、域名准备

需要准备**3个子域名**，全部解析到服务器IP：

| 域名 | 用途 | 示例 |
|------|------|------|
| 管理后台 | 商户登录管理商城 | `admin.yourdomain.com` |

| API接口 | 后端API服务 | `api.yourdomain.com` |

## 四、部署步骤

### 第0步：配置宝塔站点和反向代理

本系统采用**宝塔Nginx（SSL终止）+ Caddy（HTTP反代）**架构：

```
用户浏览器 → 宝塔Nginx(80/443, SSL终止) → Caddy(127.0.0.1:8880, HTTP) → Docker容器
```

Caddy只负责HTTP反向代理，SSL证书由宝塔统一管理。

> **建议先完成宝塔配置，再进行Docker部署，这样部署完成后即可直接访问。**

**以下操作对3个域名各执行一次（admin、h5、api）：**

**0.1 添加站点**

宝塔面板 → 网站 → 添加站点 → 填写域名 → PHP版本选"纯静态" → 提交

**0.2 申请SSL证书**

点击站点名称 → SSL → 申请/部署证书（Let's Encrypt 或其他证书）

**0.3 添加反向代理**

点击宝塔站点右侧的 **设置** → 反向代理 → 添加反向代理：

| 域名 | 代理名称 | 目标URL | 发送域名 |
|------|---------|---------|---------|
| 管理后台域名 | `admin` | `http://127.0.0.1:8880` | `$host` |
| H5会员端域名 | `h5web` | `http://127.0.0.1:8880` | `$host` |
| API接口域名 | `api` | `http://127.0.0.1:8880` | `$host` |

> **注意**：宝塔反向代理名称最少3个字符，所以H5填 `h5web` 而非 `h5`。

每个域名的站点各添加一次，填写完成后点击保存。3个站点全部添加完成后，进入下一步。

**0.4 防火墙放行**

确保 8880 端口仅允许 127.0.0.1 访问（不对外暴露）：

```bash
# 如果使用firewalld
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="127.0.0.1" port port="8880" protocol="tcp" accept'
firewall-cmd --permanent --remove-port=8880/tcp
firewall-cmd --reload
```

### 第1步：一键下载部署工具包

在服务器上执行以下命令，自动下载部署工具包到 `/opt/fenglianshop` 目录：

```bash
cd /opt
curl -fsSL https://raw.githubusercontent.com/renjie2026/fenglianshop-open/main/public-release-files/install.sh | bash
```

> cd fenglianshop-tmp && git sparse-checkout set public-release-files
> cp -r public-release-files/* ../fenglianshop/ && cd .. && rm -rf fenglianshop-tmp
> ```
>
> 克隆时遇到 `HTTP2 framing layer` 错误，使用 HTTP/1.1 重试：
> ```bash

### 第2步：配置环境变量

```bash
cd /opt/fenglianshop
cp .env.example .env
```

**必须修改的三项域名配置**（把 `yourdomain.com` 换成你的真实域名）：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| `ADMIN_URL` | 管理后台域名 | `https://admin.example.com` |
| `H5_URL` | H5会员端域名 | `https://h5.example.com` |
| `API_URL` | API接口域名 | `https://api.example.com` |

**方式一：使用 sed 一键替换（推荐）**

```bash
sed -i 's|https://admin.yourdomain.com|https://admin.你的域名.com|g' .env
sed -i 's|https://h5.yourdomain.com|https://h5.你的域名.com|g' .env
sed -i 's|https://api.yourdomain.com|https://api.你的域名.com|g' .env
```

> 将上面三行中的 `你的域名.com` 替换为你实际使用的域名，然后逐行粘贴到终端执行。

**方式二：使用 vim 手动编辑**

```bash
vim .env
```

进入 vim 后的操作步骤：

1. 按 `i` 键进入编辑模式（左下角显示 `-- INSERT --`）
2. 用方向键找到 `ADMIN_URL`、`H5_URL`、`API_URL` 三行
3. 将 `yourdomain.com` 改为你实际的域名
4. 按 `Esc` 键退出编辑模式（左下角 `-- INSERT --` 消失）
5. 输入 `:wq` 然后按 `Enter` 保存并退出

> 如果改错了想放弃保存：按 `Esc`，输入 `:q!` 然后按 `Enter`，重新编辑即可。

**方式三：在宝塔面板中编辑（适合不熟悉 vim 的用户）**

宝塔面板 → 文件 → 进入 `/opt/fenglianshop` 目录 → 找到 `.env` 文件 → 双击打开编辑 → 修改三个域名 → 保存。

> 如果宝塔文件管理器看不到 `.env` 文件，点击右上角"显示隐藏文件"即可。
>
> **备注**：需要先执行上面的 `cd /opt/fenglianshop && cp .env.example .env` 命令，才会从 `.env.example` 复制生成 `.env` 文件。

**验证修改结果：**

```bash
head -5 .env
```

输出应显示三个域名已替换为你的真实域名。

### 第3步：一键启动

```bash
bash start.sh
```

脚本会自动完成以下操作：

1. 检查Docker和Docker Compose是否安装
2. 校验域名格式和DNS解析
3. 首次运行自动生成MySQL数据库强密码（`DB_PASSWORD` 和 `MYSQL_ROOT_PASSWORD`），自动生成后写入 `.env` 文件并显示一次，请务必记录。**注意：这不是管理后台登录密码，管理后台默认账号admin，密码123123**
4. **检测到国内网络后自动配置 Docker 镜像加速器**（`docker.1ms.run`）并重启 Docker
5. 生成Caddy反向代理配置
6. 拉取Docker镜像
7. 启动全部容器
8. 等待MySQL和Redis健康检查通过
9. 安装每日凌晨3点自动备份任务
10. **交互提示**：是否安装自动更新守护进程？（建议选 Y）
11. **交互提示**：是否执行宝塔反代优化修复脚本？（建议选 Y）
12. 输出访问地址和默认账号密码

> **备用镜像源**：如果 `docker.1ms.run` 拉取失败，可手动修改 `/etc/docker/daemon.json` 中的镜像源地址，然后重启 Docker 重新部署。

**关于宝塔反代优化修复脚本**：

宝塔自动生成的反向代理配置存在以下问题，部署脚本会提示是否自动修复：

| 问题 | 说明 | 脚本自动处理 |
|------|------|-------------|
| proxy_pass 末尾多了 `/` | 宝塔自动添加，会导致路径截断 | 自动去除 |
| 缺少 `X-Forwarded-Proto` 头 | 后端无法识别HTTPS，生成错误的HTTP链接 | 自动添加 |
| Host 头为 `127.0.0.1` | Caddy 无法按域名路由到正确容器 | 自动修正为 `$host` |

如需预览将修改哪些内容而不实际执行，可稍后单独运行：

```bash
bash fix-bt-proxy-pass.sh --dry-run
```

### 第4步：安装公开版自动更新守护进程

作用说明：

1. 创建 `update-toolkit/.queue` 与 `logs` 目录。
2. 安装 `fenglianshop-public-update-daemon` systemd 服务。
3. 让管理后台"系统升级 -> 立即更新"可以把任务写入队列并由宿主机执行 `docker compose pull/up -d`。

安装完成后检查：

## 五、端口与域名说明

### 为什么只需要1个端口？

3个域名（admin/h5/api）全部通过Caddy的**同一个端口**对外服务，Caddy根据域名自动区分转发目标：

```
用户访问 admin.yourdomain.com → 宝塔Nginx(SSL) → Caddy:8880 → admin容器:80
用户访问 h5.yourdomain.com    → 宝塔Nginx(SSL) → Caddy:8880 → h5容器:80
用户访问 api.yourdomain.com   → 宝塔Nginx(SSL) → Caddy:8880 → nginx-api容器:80
```

Caddy只监听 `127.0.0.1:8880`（HTTP），不对外直接暴露，所有外部流量经过宝塔Nginx的SSL终止后转发到Caddy。

### MySQL和Redis端口

MySQL(3306)和Redis(6379)只在Docker内部网络通信，**不对外暴露**。

这意味着：如果同一台服务器上部署了多套本系统（例如用不同目录），每套的MySQL都用3306端口，**互不冲突**——因为它们在各自独立的Docker网络中，就像每套房子里都有一个"1号房间"，但房子是隔开的。

| 端口 | 对外暴露？ | 说明 |
|------|-----------|------|
| HTTP_PORT=8880 | 仅本地 | Caddy HTTP入口，仅宝塔Nginx可访问 |
| 80/443 | ✅ 是 | 宝塔Nginx SSL入口（对外服务） |
| MySQL 3306 | ❌ 否 | Docker内部通信，多套部署不冲突 |
| Redis 6379 | ❌ 否 | Docker内部通信，多套部署不冲突 |

## 六、修改默认端口

默认端口为 `8880`（HTTP），不占用80和443端口（由宝塔Nginx使用）。

如需修改，编辑 `.env` 文件：

```env
# 修改为你想要的端口
HTTP_PORT=8880
```

修改后重新运行 `bash start.sh` 生效。

**注意**：如果服务器上已有宝塔面板占用了80/443端口，保持默认的8880即可。宝塔Nginx负责SSL和对外服务，Caddy只在内部8880端口做HTTP反代。

## 七、密码持久化与更新说明

### 部署文件夹结构

部署后，所有文件都在 `/opt/fenglianshop` 目录中：

```
/opt/fenglianshop/          ← install.sh 自动创建的目录
├── docker-compose.yml      ← 容器编排配置
├── .env                    ← 环境变量（含数据库密码，自动生成）
├── Caddyfile               ← Caddy反代配置（start.sh自动生成）
├── start.sh                ← 一键部署脚本
├── fix-bt-proxy-pass.sh    ← 宝塔反代优化修复脚本
├── backup.sh               ← 备份脚本
├── restore.sh              ← 恢复脚本
├── backups/                ← 备份文件目录（自动创建）
└── ...
```

### 密码如何持久化？

首次运行 `start.sh` 自动生成的MySQL密码会**写入 `.env` 文件**。以后每次运行 `start.sh` 或 `docker compose up -d`，Docker都会从 `.env` 读取密码，**不会重新生成**。

### 如何更新到新版本？

**方式1（推荐）：通过管理后台自动更新**

```bash
# 1. 确认守护进程已安装
systemctl status fenglianshop-public-update-daemon --no-pager

# 2. 登录管理后台 → 升级与授权 → 系统升级
# 3. 激活授权后执行"检查更新 / 立即更新"
```

**方式2：手动更新**

```bash
cd /opt/fenglianshop

# 修改 .env 中的 VERSION 为新版本号
# 例如：VERSION=v6.20260610.001
vim .env

# 重新拉取镜像并启动（密码从.env读取，无需重新输入）
bash start.sh
```

**关键**：应用更新通过修改 `.env` 中的 `VERSION` 拉取新版本 Docker 镜像实现，无需重新下载部署工具包。

## 十、SSL证书说明

本系统SSL证书由**宝塔面板**统一管理，Caddy不处理SSL。

- **申请方式**：在宝塔面板 → 网站 → 点击站点 → SSL 中申请（支持Let's Encrypt免费证书）
- **续期周期**：宝塔自动续期，无需手动操作
- **证书存储**：宝塔面板管理
- **申请条件**：域名必须已解析到服务器IP，且80/443端口可访问

如果证书申请失败，检查：
1. 域名DNS是否已正确解析到服务器IP
2. 服务器防火墙是否放行了80和443端口
3. 域名是否已备案（国内服务器需要）

## 十一、常见问题

### Q1: 端口被占用怎么办？

```bash
# 检查端口占用
ss -tlnp | grep 8880

# 修改.env中的端口号
HTTP_PORT=9080

# 重新启动
bash start.sh
```

### Q2: 国内服务器拉取镜像很慢？

脚本会自动检测国内网络并尝试镜像加速。如果出现 `pull access denied for registry.cn-hangzhou.aliyuncs.com/library/caddy` 错误，是因为阿里云镜像仓库没有 Caddy 镜像，执行以下命令切换到官方源：

```bash
sed -i '/CADDY_IMAGE/d' .env
echo 'CADDY_IMAGE=caddy:2-alpine' >> .env
bash start.sh
```

### Q3: 如何更新到新版本？

```bash
# 1. 确认守护进程在线
systemctl status fenglianshop-public-update-daemon --no-pager

# 2. 登录后台 → 升级与授权 → 系统升级
# 3. 激活授权后执行"检查更新 / 立即更新"
```

### Q4: 忘记数据库密码？

```bash
# 密码保存在 .env 文件中
grep "DB_PASSWORD" .env
```

### Q5: 如何完全卸载？

```bash
# 先停止服务
docker compose stop

# 如需再执行容器清理，请先确认已完成数据库备份
docker compose down
```

> 严禁直接执行 `docker compose down -v`，这会删除数据库卷和 Redis 数据，属于不可逆操作。

## 十二、容器架构

```
用户浏览器
    ↓ HTTPS
宝塔Nginx (80/443, SSL终止)
    ↓ HTTP (proxy_pass)
Caddy (127.0.0.1:8880, HTTP反代)
    ├── admin.yourdomain.com  → admin容器:80
    ├── h5.yourdomain.com     → h5容器:80
    └── api.yourdomain.com    → nginx-api容器:80
                                        ↓
                                  api容器:9000 (PHP-FPM)
                                        ↓
                                ┌───────┴───────┐
                            MySQL:3306      Redis:6379
```

共8个容器：MySQL + Redis + API + nginx-api + Admin + H5 + Caddy

公开版升级链路补充：

- API 容器只写入 `update-toolkit/.queue/commands.json` 和 `.trigger`。
- 宿主机 `fenglianshop-public-update-daemon` 服务串行处理升级命令。
- 公开版只支持 Docker Hub 公开仓库，不需要 `docker login`。
- 不需要把 `/var/run/docker.sock` 挂载进 API 容器。
